二、六步主创作链（本包的心脏）

整套体系的推荐主流程是一条六步创作链，每步对应专门技能，前后以「文件契约」交接，任何一步发现问题都返回上游修正，不静默接管：

① story-framework
项目锁：世界观、人物、结构、规则与剧情因果
→
② script-writing
场景与行动节拍、正式剧本
→
③ script-roundtable
结构、节奏、钩子多视角会诊，回传阻断项
→
④ dialogue-doctor
角色声线、逐句改写、台词与口型时间锁
→
⑤ director-storyboard-integrated
场景闸门、方案池、正式分镜（+ 动画表现层）
→
⑥ dream-suspense-sd
批准分镜 → 纯文本 BASE LOCK + A 区块

用户批准正式分镜后才进入 Step 6；生成结果再做 QA 与回修（storyboard → 动画 → SD → 模型偏差 → 后期，按首个失败层返工）。

2.1 关键流程锁定（索引中明示的运行契约）

  • 方案讨论时先给机制不同的候选，不提前锁死单一方案。
  • 每轮只输出用户当前要求的一个阶段；未收到进入命令不跨到下一阶段。
  • 正式分镜使用完整字段、21:9 默认画幅和整秒时间。
  • 固定机位 1-4 秒内必须有信息刷新；长运镜通过内部节拍持续刷新。
  • 单段支持 4-30 秒；16-30 秒默认使用一份正式分镜、一条 SD 文本和一个 BASE，不在 15 秒重启。
  • 动画内部按 2-4 秒自然动作拍组织，12-18 秒附近必须有因果状态刷新。
  • SD 输出只使用正向、可见、可听、可执行事实。
  • 分镜是 SD 唯一源表；SD 不得改剧情、台词、镜头任务或删减构图、动作、关系、物件、环境、声光、转场和尾帧。
  • 用户侧 SD 只有纯文本 BASE LOCK + 五字段A拍；JSON 永不作为 SD 交付。
  • 项目设定只在当前任务明确点名该项目时加载。
学习要点：这套链最反直觉的规则是「分阶段门控」——不允许一次把全部产出（方案+分镜+SD）堆给用户，而是像生产流水线一样逐站放行，每站都有明确的进入命令和验收标准。

3.1 组 01-图像生成（6 个技能）

gpt-image-prompt-field-manual
GPT / DALL-E / Nano Banana 生图与改图提示词 · 源：草帽小蔡 GPT 生图提示词手册
核心规则：① 所有负向指令改写为正向视觉目标（"不要过度锐化"→"柔和边缘过渡，胶片柔光"）；② 用具体画面结果而非标签堆砌；③ 需要高级质感时加「电影质感底座包」；④ 改图/重绘先保身份、姿势、构图、场景、色调、画幅，再改质感；⑤ 脆弱画面用对比锚点"像 X，不像 Y"；⑥ 模型持续失败时拆两步工作流——GPT 出布局/主体/故事信息，Banana/Nano Banana img2img 精修纹理与边缘。
负向转正向电影质感底座纹理控制包对比锚点身份保持两步工作流
高危词提示：除非作为主体事实，避免"精细/复杂/繁复/浓郁/HDR/高细节/8K锐利/hyper-detailed"等，否则会诱发过度锐化与细节堆砌。
mj-cinematic-image-prompt
电影级 Midjourney 静帧与概念图提示词
核心原则：把提示词写成"一张被设计的图"而非松散视觉描述——① 锁定画面功能（钩子/氛围/故事信息/资产参考）；② 先选镜头（视点、景别、焦段感、景深、画幅）；③ 分层建场景（前景、主体区、中景、背景、顶/地）；④ 定义光源与阴影行为而非情绪词；⑤ 写材质、风化、尺度线索、色板与留白；⑥ 以稳定风格与渲染收尾。字段顺序固定：画风→场景身份→整体空间→主体区域→区域推进→光影结构→材质细节→整体氛围。
镜头先行分层场景光的行为化纯正向语言不加 MJ 参数（除非用户给定）纯场景禁角色
特化路由：章鱼P/2D 统一画风请求转发给 mj-takopi-2d-house-style，本技能只补充场景层次与空间构建。
mj-takopi-2d-house-style
章鱼噼 / 手绘 2D 统一画风 · 角色与场景提示词 · 参数无关 MJ 描述
核心契约：从"可见绘画证据"编译可复用的 MJ 静态描述，模型载荷中绝不出现源名、工作室、艺术家、角色名、MJ 参数。人类角色必须输出「人物执行锁」（9 字段：身份比例/姿势支点重心/脸型五官/眼睛表情/头发结构/线稿系统/平涂阴影色彩/服装手脚道具/光线响应表面质感）；场景资产必须输出「场景执行锁」（7 字段：画幅构图/机位景别/焦段景深/近中远景/光影结构/实拍材质摄影证据/实拍融合）。稳定基线：柔和的适龄剪影→手绘炭笔轮廓→成块发团→哑光面部稀疏五官大湿瞳→克制单层赛璐璐阴影→局部颊/眼下排线→简单但有重量的衣褶。
IP-Free 翻译门人物执行锁 9 字段场景执行锁 7 字段跨文化不换画风验证脚本
mj-xianxia-megastructure
仙侠巨构与巨物美学提示词（天宫、云海、悬浮宫殿、白玉京）
核心规则：围绕尺度关系构图而非装饰性仙侠设定；人物通常只是尺度标记/见证者/越界主体（占画面高度 2%-8%）。七种尺度语法：witness 见证 / threshold 门槛 / traverse 穿越 / underbelly 底部仰视 / interior-vista 内景窥外 / near-far inversion 近远大更大 / cosmic wall 宇宙尺度。必须建立至少 4 级尺度链（人→可触碰建筑/树→城/宫殿体量→大气/宇宙场）。发明一个非通用巨构行为（云瀑、悬柱、山壁宫殿、月门、倒悬城、玉质地基、地平线屋脊、星空内构）。
尺度语法 ×74 级尺度链人物 2%-8%--ar 21:9巨物行为创新
psychological-anime-imagegen
心理动画风格静态图生成与改图（校园日常 / 儿童关系压迫 / 心理近景）
核心契约：默认调用内置生图工具（非仅给提示词）。四条风格通道：DAYLIGHT-ORDINARY（明亮日常）/ RELATIONAL-PRESSURE（群体几何压迫）/ PSYCHO-CLOSE（心理近景）/ SURREAL-CONTRAST（高饱和简单吉祥物 vs 细节真人环境），最多 1 主通道 + 1 辅助通道。参考图必须分配角色（身份/风格证据/构图/编辑目标/辅助）。迭代契约：首失败层修复——每次只改一个目标层，其余保持稳定。载荷门：零标题/零片名/零"in the style of"/零分镜结构词（BASE LOCK、A区块、第X秒、运镜、转场、尾帧）。
4 风格通道参考图角色化首失败层修复IP-Free 载荷门静态图专属
qidu-aigc-prompt-atelier
七渡 AIGC 提示词修整 · 柔和电影质感 · 诺兰/星际穿越式实拍电影语言
核心规则：负向转正向；大色块优先、克制的细节、柔焦边缘、材质统一；避免在生成提示词中直接写被禁概念（可能触发模型）；对比参照"像 X 不像 Y"；人物写自然皮肤、不完美发丝、湿润高光、非摆拍动态；情绪用微表情/呼吸/凝视/身体紧张而非戏剧化表情。快速风格后缀：柔焦边缘+大色块+胶片颗粒+Kodak Portra 400 色调+电影剧照感。Qidu/Interstellar 画宪：诺兰《星际穿越》质感、霍特玛掌镜、IMAX 65mm、柯达 Vision3 5219、球面镜头浅景深、胶片化学调色、无数字锐化。
负向转正向快速风格后缀Interstellar 画宪保构图改质感

3.2 组 02-视频生成（4 个技能）

video-prompt-workbench
通用视频 / 图生视频 / 文生视频提示词工作台（含视频反推）
双模式：① 生成模式（Text→Video、Image Analysis→Prompt、Image Ref→Video、Mixed）；② 反推模式（上传视频分析/还原其提示词）。关键判断：素材将作为视频模型参考时，不要用长视觉描述替代它——参考素材是主要视觉/运动锚点，只添加运动、镜头、环境变化、风格与用户要求。反推时上传视频是唯一事实源。输出政策固定：输入类型判断→用户意图判断→中文理解→英文正向提示词→负向提示词→镜头与运动提示→推荐参数→最终可复制版本。
生成/反推双模式参考素材即锚点固定输出政策
dream-suspense-sd
梦导 SD · 六步链 Step 6 · 批准分镜 → 纯文本 SD/Seedance 提示词
唯一用户输出格式：纯文本 【BASE LOCK】+【A区块·模型执行词】。BASE 只保存跨整段稳定且影响生成的事实（媒介/参考绑定、角色身份不变量、空间轴线道具初态、光色帧感声床）；A 区块拥有所有时间变化，每个 A 拍五字段：镜头与构图 / 主体动作与表演 / 关系物件环境反馈 / 声光与转场触发 / 尾帧与连续性。JSON 永远不作为用户侧交付，即使请求明确要"JSON 视频 Prompt"。来源边界：只编译已批准正式分镜，来源覆盖默认 100%；台词逐字继承不改写；单段 4-30 秒整秒覆盖，16-30 秒一个 BASE 不在 15 秒重启；12-18 秒附近必须有一次因果刷新；普通连接动作约 0.3-1.2 秒完成。
BASE LOCK + 五字段 A 拍只编译已批准分镜来源 100% 覆盖纯文本 / 禁 JSON参考槽位名可见
图生视频/首尾帧：参考图/首帧/尾帧是约束不是故事来源；多参考图必须明确每张绑定哪些项目（人物/场景/动作/服装/构图/质感），防止权限互相覆盖。
video-shotcraft
Remotion 电影感产品视频 · 152 张镜头配方卡 + Ink Press 模板 + 六阶段流水线
三种模式（互不合并）：① 直接使用模板（Ink Press 换产品复现）；② 自主自由创作（Agent 连续推进不逐阶段确认）；③ 共同创作（产品简报→需求决策→视觉方向→镜头映射→分镜逐级确认，放行后才进入制作）。核心理念：复刻既有页面必须用真实截图（dev server + 无头浏览器全页 2x 纹理 + 元素级抠图 + layout.json）；视觉语言必须从产品自身生长（先提取设计 token 再蒙皮）；电影感来自运镜光影节奏声音而非炫技；每镜头只讲一个动效；强节奏 BGM 必须卡拍（librosa 求真实 BPM/相位 + 切点误差 ≤3f）；确定性渲染禁 Date.now()/Math.random()；交付前派独立 subagent 终检；成片默认询问是否导出剪映工程。
152 镜头卡三模式真实截图硬门槛音乐卡点 ≤3f设计 token 蒙皮剪映导出
black-subtractive-mixed-media
黑色减法揭示 · 彩色 2D 人物 × 真人底片融合 · 动态观看权限设计
核心教义：黑色是"主动空间遮罩"而非暗度滤镜——给它来源、边界、方向、覆盖变化和落定状态。三组不变量家族：实拍底片 / 彩色 2D 角色 / 跨媒介接触规则，先各自锁定再加风格润色。表演驱动开口（凝视、手、步、触、呼吸、转身让遮罩开合移动），揭示不充当与主体无关的装饰擦除。进入真人底片必须证明深度：共地接触、前景遮挡、正确投影、反射/溢色、视差/景深、环境粒子穿行（至少四项）。阶段契约严格：idea → 导演改进 → 方案池 → 用户选择/组合 → 静态资产包 → 详细分镜 → 细节批准 → SD 编译 → 结果修复。
黑色=空间遮罩三不变量族表演驱动开口深度证明 ≥4 项阶段契约失败诊断库

3.3 组 03-分镜与导演（6 个技能）

director-storyboard-integrated
一体化导演分镜 · 六步链 Step 5 · 动画/真人分镜方案、细则、连续性与 SD 承接
核心机制：① 场景可拍闸门（场景功能/入口/目标/阻力/策略/触发/节拍链/段内转折/退出变化/下一段债务，任一生病先修上游）；② 方案阶段返回 0-6 个真正不同的方案（每案写主戏剧事务/节拍骨架/画面所有者/调度机位/动画主引擎/声音物件因果/尾态/AIGC 风险），不在方案阶段输出镜头表；③ 正式分镜完整字段：段级事实锁+镜号整秒时间+戏剧变化+镜头构图+主体关系表演+物件环境 NPC+动画表达+声音台词+转场尾帧；④ 用户阶段状态机：每轮只交付当前请求阶段；⑤ 媒介路由：画面中承担主要表演的主体决定动画/非动画。实拍证据姿态 E0-E4（记忆→静帧→乱序帧→连续视频→逐帧源视频），方法证据 MTH0-4，转译标注 OBS/INF/ALT/RULE。
场景可拍闸门方案池 0-6 案用户阶段状态机E0-E4 证据分级镜头切换须有触发禁机械正反打

四、跨技能设计哲学（九条贯穿全包的规律）

1. 阶段门控，一次只交付一个阶段。从 story-framework 的七步到 black-subtractive 的阶段契约，再到 director-storyboard 的用户阶段状态机——整套体系反对"一口气全产出"，要求逐站放行、明确进入命令、验收后再前进。
2. 正向语言铁律（负向转正向）。gpt-image-prompt、mj-cinematic、qidu、dream-suspense-sd 全部执行同一规则：模型载荷只写"要生成什么"，不写"不要什么"；负面清单留在内部或人工审核附注。理由：文生图/文生视频模型可能激活被禁概念。
3. 证据分级与来源审计无处不在。video-story-analysis 用 E0-E4 屏幕证据 + MTH0-4 方法证据 + OBS/INF/ALT/RULE；scene-asset 用 O/I/U；training-maintainer 用 A/B/C；director-storyboard 转译对标用 OBS/INF/ALT/RULE。规则一致：推断不得伪装成事实，来源必须可追溯。
4. 用户侧纯文本，JSON 永不交付。dream-suspense-sd 与 director-storyboard 反复强调：用户侧 SD 只有 BASE LOCK + A 区块；JSON 只允许内部配置、测试夹具与验证器结果。可复制载荷与内部账本严格分离。
5. 无 IP 依赖（去源名翻译）。mj-takopi、psychological-anime、2d-guofeng 都把"参考了谁"留在内部证据登记，模型载荷只写可见的形状、比例、线条、明暗、色彩、光影、材质与构图，绝不出现标题/片名/工作室/艺术家/角色名/in the style of。
6. 发现上游问题就返回上游，不静默接管。director-storyboard 的六步权限、script-roundtable 只诊断不改写、animation-suspense 输入不完整返回导演层——链上每步只做自己该做的，越权即污染。
7. 时间经济与信息刷新。4-30 秒单段、2-4 秒自然动作拍、12-18 秒强制一次因果刷新、固定机位 1-4 秒内有信息、普通连接动作 0.3-1.2 秒完成、每镜只讲一个动效、高光每 4-8 秒最多一次。核心：密度衡量执行信息，不衡量拖长。
8. 表现 > 描述（反情绪词）。mystery-writer 禁"她很害怕/气氛紧张"，animation-suspense 禁"走过去、害怕、激烈打斗"作为执行内容，director-storyboard 禁用风格词/情绪词/镜头名替代可见动作。一切落到姿势、支点、路径、接触、反应、尾态。
9. 尾态继承与验证闭环。每拍尾帧=下一拍入口（SD、动画、分镜均强制）；几乎每个技能带验证脚本（validate_mj_description.py、validate_storyboard_sd.py、validate_animation_performance.py、validate_prompt.py、sandtable.py、run_static_regression.ps1 等），交付前必须过验证器，且"结构通过≠内容成立"。

七、学习心得与应用建议

7.1 这套体系的三个最值得借鉴的设计

  1. 把"创意工作"工程化成"可门控流水线"：每阶段有明确输入契约（项目锁/场景包/台词锁/批准分镜）、明确产出、明确验收，问题按职责回传上游。这解决了 AI 创作中最常见的"跑偏越改越远"问题。
  2. 以"执行密度"代替"形容词密度"：全包一致反对情绪词/风格词/水动作，要求把每个意图落成可执行的身体事实（姿势、支点、路径、接触、反应、尾态），这是 AI 生成内容质量的分水岭。
  3. 证据纪律贯穿全程：从拉片分析到训练素材入库都做分级（OBS/INF/ALT、O/I/U、A/B/C、E0-E4），"推断"永远不能伪装成"事实"，从根上防止了内容污染。

7.2 应用建议（按实际项目场景选链）

  • 悬疑短剧（目标平台抖音/视频号）：mystery-writer（用 AIGC 短剧节奏门）→ script-writing（R1 短剧节奏）→ dialogue-doctor → director-storyboard-integrated → dream-suspense-sd。参考《钟馗嫁妹》《天庭三大反骨仔》式高频刷新逻辑。
  • 2D 国风 PV / 宣传片：2d-guofeng-pv-workflow（风格 DNA + 七级阶梯）→ animation-suspense-performance → dream-suspense-sd；静帧资产用 mj-takopi-2d-house-style。
  • 产品宣传视频：video-shotcraft 三模式（推荐共同创作，逐级确认简报/方向/映射/分镜），真实页面截图 + 音乐卡点 + 独立终检。
  • 已有成片要复盘/反推：video-story-analysis（先定证据深度与报告级别）→ 可迁移规律进 director-storyboard。
  • 风格化混合媒介（2D 人物入真人）：black-subtractive-mixed-media 全阶段契约 → dream-suspense-sd 动画路线七字段。

7.3 使用注意

  • 技能包内多个 SKILL.md 引用了原始路径（F:\剧本创作四步骤\codex-skills、DOCX 源文档），归档后这些路径可能不存在——按技能说明和包内 references/scripts 实操即可，不依赖外部源文件。
  • 本包是"技能编排规则集"，不含 3D 导演台等已剥离工具；涉及真人 GUI/桌面操作（如本地软件安装验证）应另行按 computer-use 类能力处理。
  • 各技能验证脚本为 Python/PowerShell，运行前需确认本机 Python 环境；脚本说明均在各技能目录内。
