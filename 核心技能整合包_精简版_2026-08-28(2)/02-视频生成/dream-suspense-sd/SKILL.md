# Dream Suspense SD

Runtime contract: `v6.0 / 2026-08-08`

本技能是六步创作链的Step 6。它只编译已经批准的正式分镜，不重新导演、不改剧本、不重做动画表演。

## 每次必读

1. `../director-storyboard-integrated/references/runtime-contract.json`
2. `../director-storyboard-integrated/references/animation-production-pipeline.md`
3. `references/storyboard-ingestion-checklist.md`

动画项目再读 `references/animation-expanded-execution.md`；非动画项目读 `references/sd-video-advanced-execution.md`。只在命中特定问题时追加一份专项参考。

## 输入边界

合法来源按优先级：

1. 用户刚批准的正式分镜。
2. 当前任务中明确标记为批准稿的分镜文件。
3. 用户明确要求修复的既有SD文本，加上对应批准分镜。

粗略想法、方案池、对标分析、静态参考图和上一轮未批准草稿都不能直接成为SD来源。来源不足时指出缺口并停在当前阶段；不得自行发明动作、台词、镜头、转场或结局。

## 唯一用户输出格式

所有SD、Seedance、即梦、图生视频或视频提示词请求统一输出纯文本：

```text
【BASE LOCK】
媒介与参考绑定：
角色与身份不变量：
空间、轴线与道具初态：
光色、运动帧感与持续声床：

【A区块·模型执行词】
第X-X秒｜源镜头号
镜头与构图：
主体动作与表演：
关系/物件/环境反馈：
声光与转场触发：
尾帧与连续性：
```

这是唯一可复制模型载荷。不要附E表、审核说明、来源账本、评分、推理、字符预算或数值混音，除非用户明确要制作附件；附件必须与可复制提示词分开。

JSON只允许用于内部配置、测试夹具和验证器结果，永远不作为用户侧SD/Seedance交付。即使当前请求出现“JSON视频Prompt”或“单行JSON”，也说明本流程固定使用纯文本SD，并继续输出上述格式。

## 编译所有权

### BASE LOCK

BASE只保存跨整段稳定且会影响生成的事实：

- 媒介、画幅和参考图/视频/音频绑定。
- 角色身份、服装、比例和当前身体状态。
- 场景空间、轴线、屏幕方向、关键入口和固定道具初态。
- 全段光色基准、动画帧感、持续天气和声床。

参考图已锁定外貌、服装或场景时，不重新用长相描述覆盖参考。写“角色A绑定参考图1”及本段状态差量；只有易丢身份特征确实影响动作或连续性时才在A拍内就地重申。

用户侧模型载荷只能使用随请求上传后模型可见的槽位名称，例如“参考图1：场景”“参考图2：角色A”。Windows盘符、Unix绝对路径、`file://`、临时目录和工作区路径只属于内部资产账本，永远不得写进可复制的BASE或A区块。没有实际上传槽位时写“绑定随本条请求上传的场景参考图”，不得假装生成模型能访问本地磁盘。

### A区块

A拥有所有时间变化：动作、表情、视线、口型、重心、接触、道具、NPC、环境、摄影机、焦点、光色变化、声音、转场和尾态。BASE中已经稳定的事实不在每拍重复。

### 内部来源账本

写提示词前内部建立：

```text
源镜头号 -> 源时间 -> 必须事实 -> BASE/A归属 -> 易丢锚点 -> 源尾态
```

每个批准事实只能有一个主归属；所有改变像素、运动、时间、声音因果或连续性的事实必须进入BASE或A。来源覆盖默认100%。

## 五字段A拍

### 镜头与构图

写这一拍开场可见画面、画面所有者、前中后景、主体位置/比例/屏幕方向、摄影机高度/角度/起点/路径/速度变化/落点、遮挡和焦点交接。运镜必须有触发原因和最终落点。

连续跟拍或一镜到底不等于把整段写成一句“镜头跟随”。按自然动作拍写摄影机如何升降、横移、推拉、摇移、绕障、丢失和重新捕捉主体，同时保持世界方向与空间证据。

### 主体动作与表演

占每拍最大文字预算。按发生顺序写：

```text
意图/感知 -> 起始姿势和支点 -> 视线/呼吸先行
-> 肩脊髋/手脚动作与路径 -> 接触、重量、阻力和反作用
-> 峰值/过冲 -> 脸与身体错时 -> 恢复 -> 新姿势
```

普通动作也要有触发、姿势变化、关系反应和落点；高强度动作再展开完整受力。不得用“走过去、害怕、很开心、激烈打斗、自然表演”作为执行内容。

### 关系/物件/环境反馈

分别写听者/对手/NPC、道具和环境怎样继续原任务并被主体动作影响：谁先察觉、谁误读、谁延迟反应；物件的所有者、接触点、重量和新状态；衣发、纸张、烟尘、风、水、火、家具或建筑怎样延迟、回弹或落定。环境反馈必须证明动作或改变信息，不做独立装饰。

### 声光与转场触发

只写本拍真实发生的声光和媒介差量：

- 声音：具体声源、方位/距离、出现顺序、主观权限、台词窗口、重音/停顿、可见反应和尾音声桥。
- 光影：来源、方向、覆盖对象、变化时机以及它怎样改变注意力或动作。
- 转场：前态末端通过动作、遮挡、形状、方向、焦点、光或声音进入后态的完整过程。

无转场时不写空泛“自然过渡”；记录当前拍由什么动作或落点接入下一拍。数值混音留在制作附件。

### 尾帧与连续性

只写一次完整落点：结束姿势、支点、视线、屏幕方向、手和物件状态、距离、光源、持续运动、声尾、效果残留，以及下一拍从哪个未完成动作或新静止状态开始。后一拍起点必须与此相等，除非明确硬切或转场。

## 4-30秒与A拍

- 一个`4-30秒`批准段默认编译为一条纯文本提示词和一个BASE。
- `30秒`只是单条载荷上限，不是填满目标。先按批准台词实际试读、关键反应和必要动作计算“最短可执行时长”，再确定段长；情景喜剧、漫剧和快剪默认选择不损害口型与笑点的较短值。
- 快节奏对白可与走位、视线、放下道具、起身等兼容动作并行；不得把普通走近、转身、抬手、抱起分别拉成数秒展示。除非源分镜把迟缓本身定义为笑点或情绪，普通连接动作应在约`0.3-1.2秒`内完成，并以连贯的预备、发力、结果写清。
- 细致度衡量执行信息密度，不衡量拖长时长或机械字数。段长增加时，补充摄影机路径、身体力学、听者反应、物件归属、环境接力、声画因果与精确尾态；不得按比例增加停顿、走路和摆姿势。
- `16-30秒`不在15秒拆提示词或重写BASE。
- A拍通常为`2-4秒`；由动作完成、台词停顿、信息变化、遮挡节点、镜头落点或视觉状态变化决定。
- `12-18秒`附近至少编译一次有因果的信息、策略、关系、物件、焦点、声音或空间刷新。
- 额外时长用于动作准备、听者反应、环境接力、后果和恢复，不增加同一拍的并发主动作。
- 总时长超过30秒、用户明确要求多段，或动作顺序拆拍后仍不可执行时才新开提示词。每条新提示词都从上一条精确尾态进入。

## 台词编译

- 逐字继承批准台词、说话人和语言设置；不改写、不翻译、不补充。
- 明确开口、重音、停顿、闭口和尾音时间；台词前有身体准备，台词后有听者/物件/环境反应。
- 同一时间窗避免多个完整口型轨与复杂主动作竞争；抢话必须在源分镜中已批准并写明先后与覆盖。
- 不因谁说话就切给谁。摄影机只执行批准的观看权限和反应逻辑。
- 台词塞不进批准时长时停止编译，回报超载字数和需要返回的上游层，不擅自删字。

## 动画编译

动画A拍额外守住：

- 普通段的Moving Hold、低幅表演和背景任务。
- 表现段唯一主引擎的现实入口、发展、峰值、归还和残留。
- timing/spacing、阶梯帧、smear、离模/归模和画层所有权只在发生变化的拍内写。
- 特效遮挡期间保留至少一项主体证据，并说明何时把画面还给动作或关系。
- 复合运镜同时保留世界锚、摄影机路径、主体路径、遮挡连续和落点。
- 2D主体进入真人底片时同时继承透视、光向、景深、遮挡、动态接触影、反射/视差和真实材质后果。

## 图生视频与首尾帧

参考图、首帧或尾帧是约束，不是故事来源。

- 首帧已提供：BASE绑定参考；A从图中真实姿势、视线、构图、道具和光线开始，不重新设计第一帧。
- 尾帧已提供：倒推最后一拍的动作、摄影机和环境落定，使结果自然抵达目标帧；不要最后一秒瞬移摆姿势。
- 多张参考：明确每张只绑定人物、场景、动作、服装、构图或质感中的哪些项目，防止参考权限互相覆盖。
- 参考图没有展示的背面、空间连接或道具关系不能被当成已知事实；来自正式分镜的内容需明确写为新增可见区域。

## 密度与精简

精简顺序：

1. 删除同义形容和审美评价。
2. 把跨整段稳定事实上收BASE，只保留一次。
3. 删除A拍中“保持不变”的复述。
4. 合并同一因果链的环境反馈和声光触发。
5. 保留动作阶段、说听关系、接触、摄影机落点和尾态。
6. 仍过载时拆内部A拍；不得把动作压成摘要。

一拍出现第二个独立主动作、第二条复杂摄影机路径、第二次世界法则切换或无法读清的多人口型时，先顺序拆拍。不要用更多术语假装可执行。

## 正向执行词

模型载荷只写要生成什么。将否定句改成可见正向约束，例如：

```text
错误：不要切镜，不要重画人物，不要乱动背景
正确：全段保持连续摄影机路径；人物身份绑定参考图1；背景人物持续各自任务并按距离错峰反应
```

失败清单和负面诊断留在内部或制作附件，不进入可复制A区块。

## 编译步骤

1. 确认来源是批准正式分镜，锁定媒介、时长和入口。
2. 建立内部来源账本，区分BASE稳定事实和A时间差量。
3. 绑定参考图/视频/音频权限，不重述已锁定视觉。
4. 先完成台词试读与动作并行排程，确定最短可执行总时长，再以整秒`1-4秒`自然窗口覆盖；1秒拍只用于明确的反应翻转、动作接点或快速包袱。
5. 先写主体动作，再写摄影机、关系/环境、声光/转场和尾态。
6. 校验每拍结果等于下一拍入口，12-18秒刷新成立。
7. 删除重复稳定事实、抽象解释、来源名和审计文字。
8. 输出一份纯文本 `BASE LOCK + A`。
9. 运行来源覆盖、时长、字段、正向语言、动作密度、台词和连续性检查。

## 最终门

- 来源分镜100%映射到BASE或A，没有新增剧情事实。
- 4-30秒整秒覆盖；16-30秒只有一个BASE且不在15秒重启。
- 每拍一个主动作链，主体表演占最大预算。
- 台词逐字继承并有可执行口型、停顿和听者反应。
- 参考绑定清楚，不用长相描述覆盖参考图。
- BASE与A中只有模型可见的参考槽位名，不含任何本地文件路径或URI。
- 总时长来自台词与动作需求，不为接近30秒而拉长；普通走近、起身、抱起保持连贯利落。
- 摄影机有起点、触发、路径和落点；不机械正反打。
- 物件、NPC、环境、声光都由动作因果驱动。
- 每拍尾态可作为下一拍第一帧，最终尾态精确可见。
- 用户侧只有纯文本SD，没有JSON、E表、审核附录和内部推理。
